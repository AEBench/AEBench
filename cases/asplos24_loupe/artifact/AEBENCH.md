# `asplos24_loupe`

This bounded AEBench case builds the pinned ASPLOS'24 Loupe artifact and runs
its supplied Nginx/wrk example. Loupe executes two privileged container
replicas, records dynamic syscall behavior, tests stubbing and faking, and
performs static binary analysis.

It does not reproduce the full 100+ application database, paper plots,
support-plan tables, supplemental results, or performance experiments.

## Requirements

- Linux x86_64
- Docker with permission to run privileged containers
- Python 3.10 or newer with `venv`
- Git, Make, and GCC
- At least 4 CPUs, 16 GB RAM, and 30 GB free disk
- Network access during the image builds

The artifact is pinned to commit
`07ca3d25e32ebb2205c38735255084bfb8dab798`, upstream tag
`asplos24-ae-v1`. Run all commands from that checkout.

## Build

Create the small host-side Python environment and build Loupe's helper and
base image:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install 'GitPython==3.1.40' 'setuptools==75.8.2'
make src/seccomp-run
make docker 2>&1 | tee build.log
docker build --tag loupe-base:latest -f Dockerfile.aebench-compat . \
  2>&1 | tee -a build.log
```

The final build adds only an AEBench compatibility layer. The 2023 base
Dockerfile leaves its Python packages unpinned, and current package indexes
install LIEF and Capstone releases with incompatible APIs. The supplied
`Dockerfile.aebench-compat` restores the contemporary `0.13.2` and `4.0.2`
versions without changing upstream source.

Clone the artifact-evaluation database at its matching pinned tag. Loupe only
uses it as a Git-backed results store; the new `aebench-nginx` entry is not
present in the tag and will be generated by this run.

```bash
git clone --depth 1 --branch asplos24-ae-v1 \
  https://github.com/unikraft/loupedb.git loupedb
test "$(git -C loupedb rev-parse HEAD)" = \
  a076cf972d7d7bacc73693455d979a9522ed2c5a
mkdir -p aebench-results
```

## Experiment

Run the supplied Nginx/wrk example from its directory. `pipefail` preserves the
artifact's exit status while recording the complete log.

```bash
set -o pipefail
cd examples/E1
../../.venv/bin/python ../../loupe generate \
  -b \
  -db ../../loupedb \
  -a aebench-nginx \
  -w wrk \
  -d "$PWD/Dockerfile.nginx" \
  2>&1 | tee ../../aebench-results/experiment.log
cd ../..
```

The cold Docker builds dominate runtime. Leave the command running even when
the dynamic analysis is quiet; its two replicas may take a long time.

Query the newly generated database entry:

```bash
.venv/bin/python ./loupe search \
  --show-usage \
  -db ./loupedb \
  -a aebench-nginx \
  -w bench \
  2>&1 | tee aebench-results/search.log
```

Do not commit or replace the generated database output. The oracle expects the
fresh entry at:

```text
loupedb/aebench-nginx/benchmark-wrk/126e629dc544b4695f12ed602f6902aa/
```

Both CSV tables must cover syscall numbers 0 through 334. Exact classifications
are intentionally not fixed because they can vary with the host kernel and
container runtime.
